# JGD2000・JGD2011が混在するDEMの取り込み計画

作成日：2026-11-12。状態：M0〜M5の実装・検証完了（2026-11-13）。[実装・検証記録](LOCAL_TILE_MIXED_DEM_PROGRESS.md)を参照。調査基準はcommit `33f4ec1`。計画作成時にはアプリの実装・ビルド・実データの取り込み・削除を行っていない。

利用者の指示により、タイル専用の管理DB・完成DB・PNG・ジョブ履歴・作業領域は再作成できる。旧タイル資産の移行や再利用は今回の完了条件にしない。本体GIS DB、画像、設定JSON、入力PBF・DEM・陸域資料は保持する。

## 1. 目的と今回の事象

既存の同一exe・CLI管理・通常XYZ配信という構成で、国土地理院のJGD2000・JGD2011が混在するFGD-GMLを取り込み、建物・陰影・等高線を含む地図を利用できるようにする。

今回の四国の入力は、DEM ZIP 394件のうち390件が`fguuid:jgd2000.bl`、4件が`fguuid:jgd2011.bl`だった。現在は以下の2か所で停止する。

| 現状 | 修正が必要な理由 |
| --- | --- |
| `standard/elevation.rs::parse_grid`がJGD2011・JGD2024だけを受け付ける | JGD2000単独のXMLも拒否する |
| `elevation::import_into`が全入力のCRS文字列の一致を要求する | JGD2000の受入追加だけでは、JGD2011が混在した時点で再び停止する |
| DEM全体を単一の`crs`文字列で記録する | 混在資料の出典と補正の有無を表現できない |
| DEMの詳細検査がPBFの地物構築後にある | 入力条件の問題を確認するために長いPBF走査を繰り返すことになる |

直前に修正した原因チェーンの履歴保存、終了時進捗の保存、CLIの標準エラー出力は継続利用する。

## 2. 原資料を保持して併用する方針

今回の対応は、**原資料の経緯度・標高値を保持して地形背景を作る方式**とする。JGD2000をJGD2011やWGS84へ変換したと表示せず、各資料が宣言するCRSを記録する。水平位置の測地系補正・標高改定の補正は行わない。Web Mercatorへの投影と既存の格子内補間は引き続き行う。

国土地理院のビューアも、異なる測地系の併用時に境界のずれや標高差が生じ得ることを説明し、利用者が許容する場合に継続できる。[公式FAQ Q6-4](https://www.gsi.go.jp/kiban/faq.html)

四国を含む西日本の多くは、2000から2011への改定で成果値を変更しなかった地域に含まれる。一方、全国で両者を同一視することはできず、2011年には東日本を中心に基準点位置や標高が改定されている。[国土地理院時報・3.2節](https://www.gsi.go.jp/common/000084005.pdf)、[測地成果の説明](https://www.gsi.go.jp/sokuchikijun/jgd2000-2011.html)

また、DEM10A・DEM10Bは許容精度の観点から2024年の標高改定対象外であり、最新版の再取得でJGD2024に揃うとは限らない。配布ファイルの作成年月日は測量時期ではなく、2016-10-01には文字コード変更による全国差し替えもあった。[標高改定Q&A Q3-5](https://web2.gsi.go.jp/sokuchikijun/hyoko2024rev-QA.html)、[DEMの公式FAQ Q4-14](https://www.gsi.go.jp/kiban/faq.html)

### 受入条件

CLIへ`--elevation-datum-policy strict|allow-jgd2000-2011`を追加する。既定は`strict`とし、今回の取り込みでは`allow-jgd2000-2011`を指定する。追加の確認プロンプトは出さず、この指定を混在併用の選択として扱う。

| 入力のCRS構成 | `strict` | `allow-jgd2000-2011` |
| --- | --- | --- |
| JGD2000のみ | 許可 | 許可 |
| JGD2011のみ | 許可 | 許可 |
| JGD2024のみ | 許可 | 許可 |
| JGD2000＋JGD2011 | PBF走査前に拒否 | 補正未実施を注意表示して許可 |
| JGD2024とJGD2000・JGD2011の混在 | 拒否 | 拒否 |
| 未知CRS、旧日本測地系、投影座標、未対応格子 | 拒否 | 拒否 |

JGD2024との混在許可、PatchJGD等の補正パラメータによる厳密な統一、再標本化は本計画に含めない。今回の方式でも境界のずれや標高差を解消したとは保証しない。陰影・等高線の背景表示に利用する。

| M0 | CRS・混在方針・メタデータの仕様を固定する | 上の受入表と後述の識別条件をテストケースへ落とし込む |
| M1 | DEMの事前検査をCLIと取り込み開始処理へ追加する | 今回の394件の構成をPBF走査前に確認できる |
| M2 | JGD2000の読取、混在判定、出典集計を実装する | 明示指定でJGD2000・JGD2011の資料を1つの完成DBへ格納できる |
| M3 | 取り込み識別・完成検査・生成コードの確認記録を更新する | 条件が違うDB・PNGを取り違えず、コメント等では識別を変えない |
| M4 | 人工資料・実資料・実exeで検証する | 混在地形の描画、失敗時診断、決定性、既存機能の回帰を確認する |
| M5 | タイル資産の再作成手順と運用文書を整える | 再取り込み、背景再登録、オフライン表示までの手順が揃う |

### M0：仕様の固定

- `Jgd2000`・`Jgd2011`・`Jgd2024`を区別する型と、混在方針を表す型を用意する。XMLのCRS名を書き換えない。
- 対象は既存の対応FGD-GMLの地理座標格子。今回のDEM10Bを第一の実資料とし、既存の5m・10m読取を維持する。
- 混在方針は取り込み条件として保持し、再送時に同じrequest IDで条件を変えると既存どおり拒否する。
- 新しい要求項目は既定値ならJSON出力から省略し、従来の道路要求JSONとの照合を維持する。道路取り込みへの混在オプション指定は拒否する。
- 保存先は既存の4項目を使う。常駐する外部変換ツール、変換サーバー、オンライン取得を追加しない。

主な対象：`src/tilegen/standard/model.rs`、`src/local_tiles/jobs.rs`、`src/local_tiles/cli.rs`。

### M1：PBF走査前の事前検査

読み取り専用コマンド`local-tiles elevation inspect`を追加する。入力列挙とZIP構造の検査を共用し、各DEMのヘッダーからCRS・格子・収録範囲・宣言された種別を集計する。設定JSON・本体DB・catalog・生成ownerは不要とし、入力ファイルも更新しない。

`requires_database=false`の指定だけでは現在のCLI初期化を通過できないため、`main.rs`の設定JSON読込前と、`cli::execute_with_cancellation`のpool必須検査前に分岐を設ける。生成の実行認定も要求せず、未認定の実行環境でも入力の照会だけは行えるようにする。

以下は対応版で使うコマンド。実装・検証の進捗は冒頭の記録を参照する。

```powershell
[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$OutputEncoding = [Console]::OutputEncoding

& $exe local-tiles elevation inspect `
  --input $demInput `
  --elevation-datum-policy allow-jgd2000-2011 `
  --json | ConvertFrom-Json
```

- 出力はCRS別件数、単独・混在の区分、受入可否、補正の有無、注意事項を含む。今回の資料では390件／4件を確認できること。
- 終了コードは受入可なら0、混在方針等による拒否は2、読取・構文検査の失敗は1、取消は130とする。検査を実行した結果のJSONは1件とし、受入不能では`allowed=false`と理由を含める。部分集計しかできなかった場合も完了済みと表示しない。自動取り込み側も同じ検査結果を使い、拒否・検査失敗時はPBF走査へ進まない。
- 未対応CRS・禁止混在・ZIP内ZIP・暗号化ZIP・格子のヘッダー不整合は、入力ファイルとZIP内項目を示して報告する。ZIP内の項目名は診断に使い、ファイルシステムへ展開しない。
- ヘッダー検査は`validation_scope=header-only`等で範囲を示す。全標高値・CRC・欠損・終端・内容hashを検証済みとは扱わない。事前検査で保証できない走査方向等は本読取で検査する。
- 同じ事前検査を`import`のPBF全走査・大容量DB作成前にも行う。新ジョブとして受け付けた場合は、拒否理由をジョブ履歴へ残す。
- 元資料が途中で変わっていないか既存snapshotで確認し、本読取でもCRS・格子・混在条件を再検査する。
- 不要な全DEM展開や巨大な一覧JSONを避ける。既存のXML・ZIPサイズ上限、入力数上限、取消確認、I/O量とメモリの上限を維持する。

主な対象：`standard/elevation.rs`、`standard/import.rs`、`local_tiles/cli.rs`、`main.rs`。CRS等が読めない段階の例外にも、対象パスを付ける。

### M2：混在入力と来歴の保存

- JGD2000をallowlistへ追加する。単一CRS一致検査を、M0の許可表に基づく検査へ置き換える。
- 経緯度と標高値は原資料どおりに扱う。固定格子への格納、水面・水底の扱い、陰影・等高線の生成方式は維持する。
- 実資料検証で、旧DEM10Bが構成点種別「その他」に非欠損の標高値を収録していることが判明したため、XML内のDEM種別が`10mメッシュ（標高）`の場合に限り、有限・許容範囲内・`-9999`以外の「その他」も地形へ採用する。他の種別・種別未宣言での「その他」、水底、データなしは採用しない。公式仕様は種別とReal標高値を別に定義しており、この限定的な採用範囲は本アプリの実装判断として区別する。[旧配布仕様・印刷頁15〜18](https://service.gsi.go.jp/kiban/contents/screen/basismap/documents/FGD_DLFileSpecV5.0.pdf)
- 上の構成点採用規則を`effective_surface_policy`として版2メタデータ・内容SHA・取り込み条件へ保存し、完成検査でも必須値を照合する。これは実資料検証で見つかった互換性修正で、描画演算や測地系補正の追加ではない。
- 重複セルは既存の`priority`降順、同順位では内容hash順の先着採用を維持する。CRS名やファイルの更新日時を理由に自動上書きしない。
- JGD2000とJGD2011の境界を横断する補間・等高線は、採用済み格子から生成する。段差を隠すための平滑化や標高の継ぎ足しは追加しない。
- CRS名だけでは標高改定版の一致を保証できないことを、保存メタデータへ残す。
- 混在の許可判定は入力ヘッダーのCRS集合で行う。全NoDataや全セル重複の資料を含む場合でも、禁止するCRSの組合せを黙って受け入れない。一方、完成DBでは実際に採用セルを提供したCRSも別に集計する。

DEMメタデータの`revision`を2とし、次の意味を持つ情報を保存する。

| 情報 | 保存内容 |
| --- | --- |
| `source_coordinate_systems` | 並び順を固定した元CRSの一覧 |
| CRS別集計 | `input_grids`・`valid_grids`・`contributed_cells`、範囲、内容の集約hash。全NoData・全セル重複による採用0も区別する |
| `contributing_coordinate_systems` | 実際に採用セルを提供したCRSの一覧 |
| `mixed_input_coordinate_systems` | 入力資料に複数CRSが含まれたか |
| `mixed_coordinate_systems` | 実際に複数CRSを併用したか |
| 混在方針 | 指定された方針と、実際に適用した方式の版 |
| 水平位置の処理 | 原資料の経緯度を保持し、測地系補正を実施していないこと |
| 標高の処理 | 原標高値を保持し、標高改定の補正を実施していないこと |
| 検査範囲 | XML宣言・格子・許可する混在を検査し、原資料の測量時期や標高基準の一致は自動保証しないこと |

単独入力では元CRSを表示し、混在入力を架空の単一CRSへ付け替えない。`elevation.crs`を残す場合、入力CRSが複数ならnullとし、必ず元CRS一覧と併せて検証する。`mixed_coordinate_systems`は採用CRS一覧の件数から決め、入力CRS一覧の件数と混同しない。

来歴はCRS別の有界な集計として保存する。数十万のファイルを`StandardMetadata.sources`へ1件ずつ追加しない。現行の資料数上限64・メタデータ1MiB上限を保ち、エラー時に必要な個別ファイル名は診断へ記録する。

主な対象：`standard/elevation.rs`、`standard/model.rs`、`standard/store.rs`。

### M3：識別と完成検査

- 新しいDEM処理方式に合わせ、標準形式の取り込み互換性版、DEM入力識別の版、取り込み条件hashを更新する。原資料内容、採用規則、実際に適用した処理方式を識別へ含める。
- 名前、保存先、ファイル列挙順、ZIP日時、診断文、コメント、実行日時、製品版番号は、引き続き地図の識別へ含めない。
- `allow-jgd2000-2011`を選んでも、実際の入力が単一CRSで処理内容も同じ場合は、混在許可の指定だけで地図を別物にしない。指定条件はジョブに残し、DBの識別には実効的な処理方式を使う。
- 新規取り込みは新dataset IDを持ち、その結果として新render ID・新PNG保存先になる。元DBを上書きして既存PNGと結び付けない。
- `standard/store.rs::validate_metadata`の`elevation.revision == 1`固定を見直し、版2のCRS一覧・件数・補正方針・混在条件・集計を検証する。未知版、欠落、矛盾は完成DBとして公開しない。
- 地物格納表とDEMチャンクの形が変わらないため、現時点ではschema=2・geometry=2を継続する。本体`migrations/`とcatalogのスキーマ1は変更しない。
- 描画の画素アルゴリズムが変わらなければ、標準描画契約・道路描画契約の版を機械的に上げない。必要となる変更が生じた場合だけ、固定画像との比較で理由を記録する。
- `tests/fixtures/render-compatibility-review.json`を実装内容と照合して更新する。依存・コンパイラ・実行フラグを変えない場合に、実行認定を無関係に変更しない。

主な対象：`standard/import.rs`、`standard/elevation.rs`、`standard/store.rs`、識別・固定画像テスト、生成コードの確認記録。

### M4：検証

| 検証 | 確認する内容 |
| --- | --- |
| CRSと方針 | M0の全組合せ、未知CRS、既定strict、要求JSON・request IDの照合 |
| 事前検査 | inspectがDB・設定・ownerを作らず、禁止混在をPBF走査前に検出する。ヘッダー検査後の改変は本読取で検出する |
| 小さな混在資料 | 隣接・重複するJGD2000／JGD2011格子を取り込み、原標高・欠損・priorityを期待値と比較する |
| 陰影・等高線 | 人工的に連続した斜面の境界に余分な段差がないこと。原資料に段差がある場合は勝手に消さず、対応する等高線を生成すること |
| 決定性 | 入力列挙順・保存先・ZIP容器日時を変えても、同一入力内容と実効処理なら同じdataset IDと画素になること |
| メタデータ | CRS別件数・採用セル数と保存格子が整合し、版2の欠落・改ざん・矛盾を完成検査で拒否すること。全NoData・全セル重複の資料があっても入力CRSと採用CRSの集計が矛盾しないこと |
| 診断 | 原因をjob.errorへ保存し、警告が32件を超えても致命的原因を照会できること。stdoutのJSONとstderrを分離すること |
| 既存機能 | 道路の固定35画像、従来の標準地図、取消、履歴、再送、事前生成と再開、共通背景登録、通常XYZ配信 |

実資料試験にも一時の本体DB・catalog・設定JSONを用い、利用者の本体DBへ接続しない。実資料の確認は次の順とする。

1. 今回の394 ZIPを事前検査し、JGD2000 390件・JGD2011 4件、受入可、補正未実施と表示されることを確認する。
2. 各CRSの代表資料と境界を含む少数メッシュで、取り込み・陰影・等高線・メタデータを確認する。
3. 空き容量を確認した隔離保存先で、今回の四国PBF・394 ZIP・陸域による取り込みを正常完了まで確認する。終了状態は`succeeded`、dataset IDが設定済みであること。
4. debug／認定releaseで固定画像を比較し、実exeの`standard_generation_verified`を確認する。原資料を参照しない状態でも完成DBから表示できることを試験する。
5. 全国PBFの所要時間・最大ディスク量は別に実測して記録し、四国での成功を全国取り込みの実測結果とは扱わない。通常アプリの操作確認とGitコミットは利用者が実施する。

CIへ利用者の実PBFやDEMを同梱しない。自動回帰には小さな人工資料を使い、実資料での件数・選定範囲・結果は実装記録へ分けて残す。

### M5：タイル資産の再作成と利用手順

今回、旧DBの移行用マイグレーション、旧PNGの変換、失敗ジョブの途中再開は実装しない。再作成の対象はタイル専用資産に限定する。

| 対象 | 再作成時の扱い |
| --- | --- |
| `tile_catalog_database_path`と対応するSQLite sidecar | 全プロセス停止・対象確認後に破棄し、新catalogを作る。ジョブ履歴も再作成する |
| `tile_dataset_path` | タイル完成DB・完成直前DBを破棄し、PBFから作り直す |
| `tile_cache_path` | PNG・事前生成manifestを破棄し、新dataset IDで生成する |
| `tile_work_path` | 失敗ジョブ等の作業領域を破棄する |
| 本体GIS DB・画像・設定JSON | 保持する。認証・GISデータ・画像保存先・タイル保存先設定は引き継ぐ |
| PBF・DEM ZIP/XML・陸域資料 | 保持し、再取り込みに使う |

削除の前に実際の設定パスを解決し、別ディスク・再解析ポイント・ディレクトリの重なり・実行中ownerを確認する。削除対象の配下に、本体DB、設定JSON、画像保存先、入力PBF・DEM・陸域資料がないことも検査する。保全対象を含む配置はそのまま一括削除しない。`.geocode-web-single`全体や本体DBを削除するコマンドは使わない。計画作成中は削除しない。

新URLを`background add`で登録し、本体DBに残る旧`/local-tiles/`背景定義も使う場合は、取り込み完了後に共通の編集画面で新しい有効URLへ更新する。旧タイルURLを保存した共有は再作成対象として案内し、無関係な背景や共有を一括削除しない。

実装後の取り込みコマンドは次の形とする。

```powershell
$requestId = [guid]::NewGuid().ToString()
$job = & $exe @tileArgs import `
  --input $pbf `
  --name '日本・建物と地形' `
  --features standard-v1 `
  --elevation-input $demInput `
  --elevation-datum-policy allow-jgd2000-2011 `
  --landmask-input $landmask `
  --invalid-areas skip-feature `
  --request-id $requestId `
  --json | ConvertFrom-Json
```

終了コードと`state=succeeded`を確認して`$job.dataset_id`を取得し、`datasets prepare`、小範囲の`precompute plan/run`、`background add`へ進む。CLI終了後に通常アプリを起動し、共通背景一覧から選択する。

`docs/LOCAL_TILES.md`、READMEの対応範囲、CLIヘルプ、実装・検証記録を更新する。計画中のコマンドと現在利用できるコマンドを区別する。
