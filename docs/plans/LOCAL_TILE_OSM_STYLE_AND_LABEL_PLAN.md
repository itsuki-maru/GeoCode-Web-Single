# ローカル地図のOSM標準風表示と地名表示の計画

作成日：2026-11-13。状態：T0〜T7実装・検証完了。調査基準はcommit `067a93b`。確定仕様・実測・制限事項は[実装・検証記録](LOCAL_TILE_OSM_STYLE_AND_LABEL_PROGRESS.md)を参照する。

現在の建物・土地被覆・水域・地形描画へ、地名とランドマーク名、道路種別に応じた表現を追加する。OSM標準レイヤーで使われる[OpenStreetMap Carto](https://github.com/gravitystorm/openstreetmap-carto)を地図表現の参照先とし、GeoCode-Web-Single内の描画を拡張する。到達点は、日本の地域地図として名称と地物を読み分けられるOSM標準風のラスタ地図とする。

利用者の「文字」は地名・ランドマーク名を指す。最初の完成範囲では、市町村・町字・主要な自然地名・駅・主要施設を優先する。文字入力機能、住所検索、全店舗名の網羅は含めない。OSM Carto全体の移植や配信PNGとの完全な画素一致も完了条件にはしない。

## 1 維持する構成

- `src_frontend/`・`src/templates/`を変更せず、PostgreSQL版との共通フロントを維持する。
- 管理は同じexeのCLI、表示は共通背景設定と通常のXYZ PNGを使う。
- 公開URLは`/local-tiles/<dataset_id>/<render_id>/{z}/{x}/{y}.png`を継続する。
- 地物・文字・地形をバックエンドでPNGへ合成し、ラベル専用サーバーやフォント配信を必要としない。
- 本体GIS DB・共通テーブル・本体の`migrations/`は変更しない。既存の4つのタイル保存先設定を使う。
- 実装着手時に既存タイルDB・PNG・履歴の破棄許可を得た。検証は隔離領域で行い、本体DB・画像・共通設定と現用資産は変更しない。
- 原資料の経緯度・標高を保持する混在DEM方針と、旧DEM10Bの有効な「その他」を限定採用する処理を継続する。
- 描画に影響しないコメント・整形・診断・製品版番号の変更で、描画世代を変えない。

OSM標準レイヤーのスタイルはPostGIS等を前提とするため、単体アプリではその配色・分類・ラベルの階層を参考にする。[上流README](https://github.com/gravitystorm/openstreetmap-carto/blob/master/README.md)、[地図表現の設計方針](https://github.com/gravitystorm/openstreetmap-carto/blob/master/CARTOGRAPHY.md)

## 2 現状と必要な変更

| 現状 | 必要な変更 |
| --- | --- |
| `pbf.rs`のNodeにはタグがなく、通常Node・DenseNodeともタグを検査後に捨てる | 新しい取り込みで必要なNodeタグを取得する経路を追加する |
| `standard/import.rs`は道路・対応する面や線と、その構築に必要なNodeだけを選ぶ | 独立した地名・山頂・施設Node、名称付き地物を選択する |
| 作業DBにあったWay・Relationのタグも、完成DBでは主に分類・形状・構造へ集約する | 名称群、重要度の根拠、道路・水路・鉄道等の細分類を完成DBへ保持する |
| 道路は8分類だが、主要な道路の塗り色は共通 | 種別別の色・幅・縁取り・破線と、橋・トンネルの表現を設ける |
| `standard/paint.rs`は面・線・陰影だけを描く | 固定フォントによる名称描画、配置、衝突抑制を追加する |
| `RenderOptions`は予約領域だけで、形式ごとに描画契約が1つ | 不変の描画設定から複数の描画世代を作る |
| runtimeはDatasetHandleだけでセッションを再利用し、常に既定設定を渡す | データセットと描画設定の両方でセッション・キャッシュを区別する |
| catalogのprofile表には既に複数profileを保存できる | スキーマ1を維持し、`info_json`へ版付きの設定を保存する |

既存完成DBから名称や未保存の道路細分類は復元できない。名称を表示するためにPBFから新しい完成DBを1回作る。その後の色・表示レイヤー・文字の表示言語の切替は、保存済みの原情報で対応できる範囲では再取り込みを要求しない。

## 3 表示する名称と地物

| 対象 | 最初の対応範囲 |
| --- | --- |
| 地名 | `place`の市・町・村・集落・郊外・町字相当・島。行政Relationの名称と有効な代表Nodeも補助に使う |
| 自然地名 | 名前のある山頂・火山・峠・島・湖・主要河川 |
| ランドマーク | 駅・空港・役所・学校や大学・病院・公園・博物館・城跡等の主要観光施設。タグの許可表で選択する |
| 道路 | 高速・幹線・一般道・生活道路・サービス道路・歩道等の階層別の色と線幅。橋・トンネル・リンクを区別する |
| 地表・水域 | 森林・公園・農地・住宅地・商業地・工業地・建物・海・湖・川の配色と表示順を調整する |
| 地形 | 現行のDEM・陰影・等高線を選択表示できるようにする |

名称は`name`・`name:ja`・`name:en`・`int_name`・`short_name`等の必要な原情報を保存する。日本語設定は`name:ja → name → int_name → name:en`、現地名設定は`name`を優先する。自動翻訳やオンライン照会は行わない。省略名を使う条件も固定規則にする。

大きな地名を低いズームから、町字・主要施設を高いズームから表示する。初期の品質確認は地域地図のズーム6〜17を中心に行い、収録範囲外の名称を補って全国・全世界の網羅を装わない。道路名・国道番号の盾・一方通行矢印・全店舗の記号・複雑な線に沿う文字配置は後続の拡張対象とする。河川名は最初から対象とし、まず線全体から求めた安定した代表位置へ配置する。

## 4 生成時オプション

生成時オプションの中心は、完成DBからPNGを作る際の描画設定とする。取り込み時に道路等を削り落とさず、同じDBから異なる背景を作れる構成にする。

| 描画項目 | 新しいOSM標準風設定の既定値 | 意味 |
| --- | --- | --- |
| 道路 | on | 道路線を表示する |
| 建物 | on | 建物の面と輪郭を表示する |
| 地名・ランドマーク名 | on | 優先順位と密度に応じて名称を表示する |
| 等高線 | off | 必要な背景でだけ有効にする |
| 陰影 | off | 必要な背景でだけ有効にする |
| 名称の言語 | ja | 原資料の名称群から日本語優先で選ぶ |

スタイルの識別名は`osm-like-v1`案とする。同じスタイルで等高線・陰影をonにすれば地形付きの背景、道路をoffにすれば道路線を省いた背景になる。建物offは建物面の非表示であり、施設名は名称の設定で独立して制御する。等高線offでも山名は表示できる。道路名を後で追加した場合は道路offと連動させる。

等高線の計算時間・DB容量を省きたい用途には、取り込み側の`--contour-data on|off`も追加する。既存の`standard-v1`の挙動は変えず、新形式でもDEM指定時の既定はonとする。offで作ったDBに後から等高線表示を要求した場合は、データ不足を明示して拒否する。新しい完成DBの作成が必要となり、閲覧中に黙って大規模計算を始めない。等高線を収録済みのDBなら、表示のon/offだけで再取り込みは不要である。

DEM自体を省略したDBでも通常の名称付き地図を作れる。陰影・等高線をonにする場合は、対応するデータの収録を検証する。

## 5 新しい完成DB

新しい取り込みモードを`--features standard-v2`、完成DBをschema=3／geometry=2とする案で進める。既存の線・面BLOB形式は継続し、点の名称候補は別表へ保存する。形式番号・メタデータ版・読み取り分岐はT0で確定する。

- 通常Node・DenseNodeの両方に、選択タグを取得する読取モードを追加する。既存の道路走査のNode型や既定の割当量を不用意に増やさない。
- Relation・Wayの選択と必要Nodeの解決を行う既存の3走査を拡張する。独立した地名・施設Nodeは、Wayに参照されていなくても拾う。全Nodeをメモリへ保持しない。
- 行政Relationは`label`・`admin_centre`等の必要Nodeを先に収集する。有効な代表位置が取れない場合に、切り出し境界を勝手に閉じたり、欠けた行政面を無理に構築したりしない。
- 名称候補表には元OSM種別・ID、カテゴリ、名称群、重要度の根拠、世界座標の代表点、元の線・面への参照、重複整理情報を持たせ、位置検索用のRTreeを設ける。
- 道路には元の`highway`・`service`・`surface`・`access`・`oneway`・`ref`等の必要属性、水路・鉄道・土地被覆には必要な細分類を保存する。表示ズームやフォントによる文字幅は描画設定側で決める。
- 名称・選択タグに1地物当たりの長さと合計サイズの上限を設け、超過した名称候補の除外理由を集計する。PBF全体の文字列を無制限に完成DBへ複製しない。
- 面の名称位置は穴の中へ置かず、対象の面内へ求める。線の代表位置はタイルで切った線ではなく、保存した線全体から求める。
- 現在の面分類に入らない名称付き施設のWay・Relationも、代表位置に必要な形状を解決する。既存の面描画へ分類できないという理由だけで、対象施設の名称を捨てない。
- Nodeと同名の面、Relationとmember Way、駅と同名の施設候補を整理する。同じ名前という理由だけで、離れた別の地名を統合しない。

新DBの識別には原資料・抽出規則・格納属性・代表位置の計算方式・等高線の収録条件を含める。既存DBのdataset IDを再計算したり、既存ファイルへ新テーブルを書き足したりしない。名称件数・カテゴリ別件数・除外理由・収録能力を別に記録し、既存の形状件数と区別する。等高線作成の省略は新形式の版付き能力として記録し、旧DEMメタデータの完成条件を変えて既存DBを再解釈しない。

本体migrationとcatalogの既存SQLは変更しない。新形式対応では`store.rs`・`dataset.rs`・`identity.rs`・`service.rs`等の形式判定を明示的に拡張し、形式1／1・2／2も引き続き読み取る。

## 6 フォントとラベル配置

日本語・かな・漢字・ラテン文字を描く固定フォントをexeへ同梱する。候補はNoto Sans CJK JPで、OSのインストール済みフォントや起動時のダウンロードへ依存させない。フォントの版・ファイル内容・ウェイト・字形選択・欠字時の扱いを固定する。[Noto CJK](https://github.com/notofonts/noto-cjk)、[同梱ライセンス](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)

字形の選択・配置はHarfRust、輪郭取得はSkrifa、画素化は既存のソフトウェア描画を利用する構成を候補とする。CJKフォントの実形式、文字結合、異体字、実行環境間の再現性、exe増加量を小さな試作で確認して採用版を固定する。RustyBuzzは上流で保守終了と後継移行が案内されているため、新規採用の第一候補にしない。[HarfRust](https://github.com/harfbuzz/harfrust)、[Skrifa](https://github.com/googlefonts/fontations/tree/main/skrifa)、[RustyBuzzの案内](https://github.com/harfbuzz/rustybuzz)

文字は白い縁取りを付け、ズーム・カテゴリ・重要度で大きさや色を変える。原名称を保持し、描画時だけ所定の幅での改行・短縮名・省略を適用する。日本語の禁則、結合文字・異体字の途中で分割しないこと、欠字の固定表示と診断を確認する。フォントと著作権・OFL表示を同梱し、CLIから確認できるようにする。

ラベルはタイル単位の欲張りな配置にしない。次の初期方式をT5で実装する。

1. ズームごとの世界座標で、元地物・カテゴリから優先度と代表配置を一意に決める。文字の縁取りを含めた矩形を使う。
2. 優先度の同順位は元OSM種別・ID等で必ず順序を固定する。最初は候補ごとに1つの代表配置とし、複雑な再配置は加えない。
3. 表示候補は、重なる上位の原候補がない場合に採用する。上位候補が最終的に採用されたかを再帰的にたどらない、有界な競合判定にする。密集地で保守的に間引かれることは許容する。
4. 最大文字幅・高さ・縁取り・離隔から、描画対象候補の範囲と、それを抑制し得る上位の原候補の範囲を別々に導出し、両方を取得する。文字が見える範囲だけの余白では済ませず、道路や面の検索余白とも混同しない。
5. 決定した文字全体を世界座標の同じ位置で描き、最後に256pxへ切り出す。タイル外に代表点がある名称も、文字がタイル内へ入る場合は対象にする。

単に余白を広げたり、4枚の画像をまとめたりするだけでは、配置判定の連鎖による境界差は解決しない。上の局所的で確定的な判定を先に成立させる。複数の代替位置や線に沿う配置を導入する際は、配置規則の版と境界テストを更新する。

候補数・文字長・画素幅・字形キャッシュ・処理量・取消確認には上限を設ける。候補の間引きはズームごとの世界固定セル内で重要度と安定した順序に従って行う。描画窓全体に対する先頭N件の抽出で候補集合を変えず、隣接タイルと大きな描画窓が同じ候補を比較できるようにする。処理順やキャッシュの状態でも表示を変えない。

## 7 描画設定と世代管理

CLIで指定した値を、既定値も解決した版付きの不変`RenderSpec`へ正規化して保存する。profileは名前付きの可変設定ではなく、特定の描画内容を表す記録とする。

- `datasets prepare`でスタイル・表示項目・言語からprofileを作り、render IDを返す。`info_json`へ設定と契約を保存する。
- `precompute`・再開・`url`・`background add`・HTTPのcache missは、指定render IDの設定を同じ方法で解決する。事前生成のときだけ効く設定にしない。
- データセットだけを持つワーカー処理を改め、セッションの再利用条件をデータセット＋描画設定にする。SDKのcache key、キューの共有、PNG保存先も一致させる。
- 色・線幅・表示項目・名称選択規則・実使用フォントの内容hash・文字配置規則等を描画契約へ含める。文字offでは、未使用フォントや言語の差を識別へ入れない。
- コメント・製品版・ビルド来歴・保存先・worker数・背景の表示名は描画識別へ含めない。別の指定でも実効設定が同じなら同じrender IDにする。
- 名称の追加収録は新dataset ID、同じDBの表示切替は新render IDとする。新しい契約の識別領域を設け、旧identity version 2／3のバイト列とIDを変更しない。
- 既存の道路・地形描画の経路を維持し、固定画像で一致を確認できる旧profileは生成・再開も継続する。再現できない契約は既存仕様どおり保存PNGの配信に限定し、未生成分を新しい見た目で補わない。
- 指定省略時は形式ごとの固定の既定設定を使い、profile一覧の先頭や作成日時で選ばない。既存の要求JSON・manifestの既定補完を保ち、過去ジョブを別設定へ読み替えない。
- 能力のないDBへ名称・陰影・等高線を要求した場合は理由を返す。名称がない既存DBを名称対応済みと扱わない。

背景追加には表示名の個別指定も設け、同じDBの通常地図・地形付き地図を共通背景一覧で区別できるようにする。フロントへ専用の表示スイッチは追加しない。

## 8 実装順序

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| T0 | 比較基準と仕様を固定する | OSM Cartoの参照版、地物・名称の許可表、ズーム、既定値、資源上限、旧互換性、新形式を定義する |
| T1 | 複数描画設定の基盤 | CLI・SDK・runtime・profile・識別・再開を同じ不変設定で接続し、同じDBの異なる表示を混在させない |
| T2 | 名称と詳細属性の取り込み | 通常Node・DenseNode・Way・Relationを対象とする新完成DBを作り、名称・代表位置・件数・能力を完成検査する |
| T3 | 固定フォントと文字描画 | 日本語・ラテン文字・結合文字・欠字を処理し、同梱フォント・ライセンス・字形キャッシュ・実行認定を整える |
| T4 | OSM標準風の地物描画 | 道路の階層、配色・線幅・縁取り・破線、橋・トンネル、建物・土地被覆・水域の可読性を調整する |
| T5 | 地名とランドマークの配置 | 地名・自然地名・主要施設が密度に応じて表示され、タイル境界・実行順で文字が変わらない |
| T6 | CLIと通常XYZへの統合 | 描画設定別の事前生成・再開・背景名・HTTPの未生成PNGが一致し、オフラインで利用できる |
| T7 | 四国実資料・配布exe・回帰と運用 | 新DBを隔離して作成し、比較画像・固定画像・性能・旧資産保持を確認し、切替手順を整える |

T0〜T1で契約を固定した後、T2・T3・T4の独立部分は並行作業できる。T5以降は同じ確定仕様へ統合する。最初の完成範囲はT0〜T7とし、文字なしのスタイル変更だけをもって完了とはしない。

## 9 実装したCLI

以下のオプションを実装済み。ビルド・検証済みexeと運用手順は[ローカル地図](../LOCAL_TILES.md)と実装記録を参照する。`$exe`・`$tileArgs`・入力パス・UTF-8設定等は現行手順と同じものを使う。

```powershell
# 現在のDBを残し、名称対応の別DBを作る。
$job = & $exe @tileArgs import `
  --input $pbf --name '四国・名称対応' --features standard-v2 `
  --elevation-input $demInput `
  --elevation-datum-policy allow-jgd2000-2011 `
  --landmask-input $landmask --contour-data on `
  --invalid-areas skip-feature `
  --request-id ([guid]::NewGuid().ToString()) --json | ConvertFrom-Json
$id = $job.dataset_id

# 通常地図。道路・建物・名称を表示し、等高線・陰影を省く。
$normal = & $exe @tileArgs datasets prepare --dataset $id `
  --style osm-like-v1 --roads on --buildings on `
  --labels on --language ja --contours off --hillshade off `
  --json | ConvertFrom-Json

# 同じDBから地形付きの描画世代も用意する。
$terrain = & $exe @tileArgs datasets prepare --dataset $id `
  --style osm-like-v1 --roads on --buildings on `
  --labels on --language ja --contours on --hillshade on `
  --json | ConvertFrom-Json

& $exe @tileArgs background add --dataset $id `
  --render $normal.render_id --name '四国・通常地図' | Out-Host
& $exe @tileArgs background add --dataset $id `
  --render $terrain.render_id --name '四国・地形付き' | Out-Host
```

道路を省く背景も`datasets prepare --roads off`で別profileとして作る。事前生成はそのrender IDを指定する。背景登録後はCLIを終了し、共通の背景一覧から選択する。名称追加のための新規取り込み後は、表示項目を変えるたびにPBFを読み直す必要はない。

新スタイルは独立した固定画像を作り、既存42画像を置き換えない。文字エンジン・フォント・実際の色や配置の変更を生成コード確認記録と実行認定へ反映し、旧描画系列の依存指紋を無関係に変更しない。取得する上流コード・フォントは版と内容hashを固定し、スタイル・素材・フォントの同梱条件を個別に確認する。[OSM Cartoのライセンス](https://github.com/gravitystorm/openstreetmap-carto/blob/master/LICENSE.txt)

四国での成功を全国PBFの容量・所要時間の実測とは扱わない。実装・ビルド・取り込みの検証結果は別の進捗記録へ保存する。通常GUI・PC／モバイル・印刷・共有の確認とGitコミットは利用者が実施する。
