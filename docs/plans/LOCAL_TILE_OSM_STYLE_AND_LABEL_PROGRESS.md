# OSM標準風表示と地名表示の実装・検証記録

対象計画：[OSM標準風表示と地名表示](LOCAL_TILE_OSM_STYLE_AND_LABEL_PLAN.md)。2026-11-13にT0〜T7の実装・検証を完了。

## T0 確定した仕様

比較する表現は[OpenStreetMap Carto v5.9.0](https://github.com/openstreetmap-carto/openstreetmap-carto/tree/v5.9.0)の道路階層・地表配色・名称の階層とした。配信PNGの複製やCartoCSSの実行ではなく、本体のソフトウェア描画で表現する独立スタイル`osm-like-v1`を追加する。後続の上流更新で自動的に外観が変わる仕組みは持たない。

| 項目 | 確定値 |
| --- | --- |
| 取り込み | `--features standard-v2`、完成DB schema=3 / geometry=2、拡張メタデータrevision=2 |
| 従来形式 | roads-v1=1/1、standard-v1=2/2の読み取り・既定描画を維持 |
| 描画契約 | identity version 4、RenderSpec revision 1、旧identity 2/3の識別バイト列を維持 |
| 通常地図の既定 | 道路・建物・名称on、日本語優先、等高線・陰影off |
| 取り込み時等高線 | standard-v2のみ`--contour-data on|off`、既定on。offでもDEMと陰影用データを保持 |
| フォント | Noto Sans CJK JP Regular 2.004、OTF 16,467,736 bytes、SHA256 `68a3fc98800b2a27b371f2fb79991daf3633bd89309d4ffaa6946fd587f375b5` |
| 字形処理 | HarfRust 0.16.0、Skrifa 0.50.0、固定フォントの非hinting輪郭を本体で画素化 |
| 配置 | 世界固定128pxセル、1セル最大16候補、上位の原候補との非再帰競合、同順位は元OSM種別・ID・カテゴリで固定 |
| 名称上限 | 1名称512 bytes、1地物の名称合計2,048 bytes、描画は48 grapheme・224px幅・最大2行 |
| 処理上限 | 1照会100,000候補／16MiB、1描画4,096レイアウト／131,072字形、字形キャッシュ512項目 |
| 保存先・配信 | 既存4設定・catalog schema1・XYZ URLを継続。本体migrationと共通フロントの変更なし |

固定フォント・著作権・OFL全文をexeへ同梱し、`local-tiles build-info --json`から確認できる。OSのフォントやオンライン文字サービスは使用しない。

名称の抽出許可表は`standard/labels.rs`で固定し、市町村・集落・町字・島・山頂・峠・湖・河川、駅・空港・役所・学校・病院・公園・主要観光施設を収録する。元の`name`・`name:ja`・`name:en`・`int_name`・`short_name`を保存し、日本語は`name:ja → name → int_name → name:en`を優先する。地物Nodeと同名の面、Relationとmember Wayは近接・構造条件も確認して整理する。

主な表示開始ズームは市5、島7、町8、行政代表名・湖9、村・空港10、山頂・峠・河川11、集落・郊外・町字12、駅13、近隣地区・公園・主要施設14。建物面は従来どおり14以上。道路名・道路番号の盾・線に沿う名称・全店舗記号は今回の範囲に含めない。

橋・トンネルの色・太さ・破線の強調は13以上で使う。低ズームは通常道路と同じ表現にし、短い橋が太い丸点に見えることを避ける。橋を水面より後に描く等の構造による順序は維持する。

孤立集落は15、小字・その他の地名は13から表示する。名称のないズーム0〜4は名称DBを照会せず、それ以降も当該ズームの表示分類だけをSQLで取得する。高ズーム用の施設が多数あっても、低ズームの候補上限を消費しない。

競合相手の照会余白は、可視候補の代表点までの最大半径H、可視候補の反対側の外端までH、競合相手の代表点までHを含む。両方の衝突余白Pと丸めを足した`3H + 2P + 2px + 1/64px = 390.015625px`を全方向へ確保し、その後に世界固定セル全体へ広げる。描画窓外の上位候補による抑制も隣接タイルと揃える。

## T1〜T6 実装

- 不変のRenderSpecをprofileへ保存し、SDK・事前生成・再開・HTTP生成workerへ同じ設定と契約を渡す。セッション再利用とPNG保存先はdataset＋render IDで区別する。
- standard-v2の3走査で通常Node・DenseNodeの選択タグ、独立地名、名称付きWay・Relation、行政代表Nodeを解決する。名称候補と詳細属性を別表へ格納し、完成検査・件数・除外理由・能力を記録する。
- 道路8分類、橋・トンネル・経路の破線、地表・建物の配色を追加した。既存描画経路の色・描画順は変更しない。
- 文字はフォントの内容と配置規則を描画識別へ含める。名称offでは言語を正規化し、未使用フォント・配置規則を識別から除く。
- 名称・陰影・等高線に必要な収録能力を検査し、不足時は理由を返す。旧DBに名称を後付けしたと見なさない。
- 背景の`--name`を追加し、同じ完成DBから通常地図と地形付き地図を共通背景一覧へ登録できる。

地域資料の収録範囲外は中立色になる。名称は許可表にある元データだけを表示する。河川名はWay／Relationの代表点へ置く初期方式なので、PBF上で同じ川が複数Wayへ分かれている場合は同名が繰り返されることがある。線に沿う文字配置や道路名・番号の盾、全国での容量・時間の実測は後続対象。通常GUI・PC／モバイル・印刷・共有の確認とGitコミットは利用者が実施する。

利用者から既存タイルDB・PNG・履歴の破棄許可を得ているが、検証ではworkspaceの隔離領域を使う。利用者の本体DB・設定JSON・画像・現用タイル保存先へ書き込まない。
