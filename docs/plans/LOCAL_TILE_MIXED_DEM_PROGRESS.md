# 混在DEM対応の実装・検証記録

対象計画：[JGD2000・JGD2011が混在するDEMの取り込み計画](LOCAL_TILE_MIXED_DEM_PLAN.md)。作業開始日：2026-11-12。状態：M0〜M5の実装・自動回帰・四国実資料による実exe試験を完了（2026-11-13）。全国PBFや通常GUIの確認とは区別する。

## 実装

- 原CRSを型で区別し、`strict`と`allow-jgd2000-2011`を追加した。既定値は要求JSONから省略し、従来の道路要求を維持する。
- `local-tiles elevation inspect`は設定JSON・本体DB・catalog・生成認定を使わず、ヘッダーだけを有界に検査する。
- PBFの走査・大容量作業DB作成前にも同じ検査を行う。事前検査後の入力一覧・priority・ZIP構造・ファイルの変化を本読取前に確認する。
- 元の経緯度・標高値を保持し、入力CRSと採用CRSを区別した版2メタデータを完成DBへ保存する。
- 単独入力は混在許可の指定だけでdataset IDや画素を変えない。標準形式の取り込み互換性を更新し、実効的な処理方式を識別へ含める。
- 完成検査では出典・保存文書・実格子の件数を照合する。DEM出典がないのに格子だけが残る不整合も拒否する。
- 陰影・等高線・道路の画素演算、描画契約、本体migration、catalogスキーマ、共通フロントは変更しない。

## 実資料の扱い

実PBF・DEM・陸域は読み取り専用の入力として使う。実資料試験は一時の本体DB・catalog・設定JSONとworkspace内の専用出力を使い、利用者の本体DBへ接続しない。入力一式のファイル集合・サイズ・更新時刻・SHA-256を前後比較する。

旧タイル資産の自動削除や、利用者の設定JSON・本体DB・画像の変更は行っていない。タイル資産の再作成範囲と手順は[運用文書](../LOCAL_TILES.md)へ追記した。

## 実資料検証で見つかった監視停止

最初の隔離試験では、PBFからの地物構築中に管理DBの進捗が221秒で停止した。生成用DB自体はその後も約305秒まで更新されたが、履歴確定へ進まず、CPU使用時間も増えなくなった。

取消監視の`select!`の枝内で管理DB照会を待つ間、取り込みfutureをpollしていなかった。取り込み側も同じ管理DBの初期化用FIFO mutexを待つタイミングが重なると、後着の照会が先着側の再開を妨げ得る。取消監視を独立したfutureとして実処理と並行pollし、DB照会が待機中でも実処理の完了を受け取る回帰を追加した。

実際の管理DB接続を4本とも保持する回帰は、旧実装で失敗し、修正後に成功した。既存の外部取消・実ワーカーの終了待機を含む取消関連4件と、`cargo test --locked --offline --lib local_tiles::`の19件も成功した。完了結果を先に扱い、取消では実処理をdropせず終了を待つ条件を維持する。出力は`monitor-regression-before.log`・`monitor-regression-after.log`へ保存した。

停止した試験は、実行パス・親子関係・隔離設定パスを照合した2プロセスだけを終了した。出力と診断は`stalled-run.json`および`real-8c8cc258-a828-4e87-bb5d-af659e8fdabd/`へ保管し、利用者の実行中アプリや保存先は操作していない。

## 実DEM10Bの構成点種別への追加対応

監視修正後の隔離試験は標高読取まで進んだが、「有効な地表・表層の標高セルがありません」で終了した。今回のXMLでは「その他」に有効な標高も収録され、従来の読取が一律に欠損へ分類していたためである。例えば`493226`は843,750セルすべてが「その他」で、非欠損の実標高を持つ。

XML内のDEM種別が`10mメッシュ（標高）`の場合だけ、「その他」の有限・範囲内・`-9999`以外を採用するよう調整した。他種別・種別未宣言の「その他」、水底、データなしの除外は維持する。ファイル名やCRSで推定せず、`effective_surface_policy=source-ground-surface-and-10m-other-v1`をメタデータ・内容SHA・取り込み条件へ保存して完成検査で照合する。[配布仕様の種別・標高定義と実装上の採用範囲](../LOCAL_TILES.md)を参照する。

- 旧仕様で合成回帰の失敗を確認し、修正後に成功した。
- 標準処理の40件が成功した。環境変数による実資料SDK試験1件は通常実行時のignoreを維持する。
- JGD2000の`FG-GML-493226-DEM10B-20161001.zip`とJGD2011の`FG-GML-503243-DEM10B-20181114.zip`を実SDKで取り込んだ。採用846,887セル（843,750／3,137）、等高線3,864件、標高0〜867mで、保存格子の集計と一致した。5.54秒で成功した。
- ログは`dem-other-regression-before.log`、`dem-other-regression-after.log`、`dem-other-standard-suite.log`、`representative-dem-smoke.log`。代表資料一覧は`representative-dem-inputs.json`へ保存した。

追加対応前の実exe試験は`real-31b35e38-114f-4f34-81b9-e1074f1653e4/`へ保持している。長時間試験の失敗出力はログ末尾16KiBと完全ログのパスに制限し、進捗履歴全体をpanic本文へ重複出力しないようにした。全target再検査は、Windowsで使用中のテストexeへ再リンクしないよう、実資料のテスト実行と順番を分ける。
