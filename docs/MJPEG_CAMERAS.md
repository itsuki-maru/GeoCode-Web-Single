# 公開ライブカメラ（MJPEG画像）

マーカーの詳細に次のMarkdownを記載する。`camera`は小文字の固定識別子。

```markdown
![camera](https://camera.example.com/stream)
```

URLは認証情報を含まない絶対HTTPまたはHTTPS URLにする。ページのURLではなく、`multipart/x-mixed-replace`でMJPEGを返す配信URLを指定する。相対URL・data URL・ユーザー名/パスワード入りURLは受け付けない。クエリー文字列は変更せず、`thumb=true`も追加しない。`/snapshot`のJPEGを指定した場合は静止画になり、自動更新されない。

LAN内のHTTP配信は、GeoCode-Webサーバーの環境変数に配信元を登録してから、次のように指定する。配信元は閲覧端末から到達できるアドレスで待ち受けている必要がある。

```markdown
![camera](http://192.168.1.20/stream)
```

Pi側の導入ツールはループバック待受のため、LANでの配信にも視聴用パスを転送するプロキシ等が必要。上の例は[Caddyの導入とLAN公開手順](../GeoCode-Web-CameraStreamer/docs/PUBLISHING.md)に従い、80番ポートで配信する場合のURL。camera-streamerの8080番ポートは閲覧端末から直接指定しない。

## HTTP配信元の許可設定

GeoCode-Webサーバーの環境変数（または読み込まれる`.env`）に、実際の配信元を設定する。Pi側の`config.json`の設定ではない。

```dotenv
HTTP_IMAGE_ALLOWED_ORIGINS=http://192.168.1.20,http://192.168.1.21:8080
```

- HTTPS画像は設定なしで従来どおり許可する。
- 未設定・空文字列ではHTTP配信元を追加許可しない。従来のCSPの`'self'`は維持する。
- カンマ区切りの`http://IPv4[:ポート]`のみ。ポートは1〜65535、省略時は80。前後の空白は除去し、重複はまとめる。
- ホスト名・IPv6・認証情報・パス（末尾の`/`も含む）・クエリー・フラグメント・ワイルドカードは指定できない。不正値は起動エラーになる。
- 許可はカメラ専用ではなく、その配信元の画像全般に適用される。`ALLOW_ORIGINS`とは別の設定。
- 設定変更後はサーバーを再起動して地図ページを再読み込みする。IPが変わった場合は環境変数とマーカーのURLを更新する。

HTTPを一括許可していた版から更新する場合は、先にこの環境変数を設定してから再ビルド・再起動する。未設定だとHTTPカメラはCSPでブロックされる。ページの応答ヘッダーの`Content-Security-Policy`で、`img-src`に指定元があり、単独の`http:`がないことを確認する。別のプロキシでもCSPを付けている場合は、その制限も適用される。

HTTPSの地図からHTTP画像を読み込む場合、ブラウザの混在コンテンツ制限が別途適用される。Chromeではローカルネットワークへのアクセスを許可すると、プライベートIP等のHTTP配信が読み込める場合がある。初回に確認が表示されたら、信頼する配信元であることを確認して許可する。今回の実機では、この許可により表示できた。ブラウザや端末によってはHTTPS配信が必要になる。参考：[Chromeのローカルネットワークアクセス](https://developer.chrome.com/blog/local-network-access)。

## 動作

- PC・モバイルの通常地図、別画面、一時共有地図、公開ライブマップの公開レイヤで表示する。図形メモでも同じ記法を使える。
- ポップアップを開いたときだけ画像を生成して受信する。閉じる、地図から取り除く、折りたたみを閉じる、ページを非表示にする、ページを離れると受信を解除する。
- 再表示時は開いているポップアップだけ再接続する。閉じたポップアップを自動で開くことはない。
- 「再接続」で手動復旧できる。自動リトライを繰り返さない。通常画像の拡大プレビューには接続しない。
- Markdown編集プレビューでは案内文だけを表示する。保存後に地図のポップアップで確認する。
- 印刷プレビュー・PDFでは映像を含めず案内文に置換する。ブラウザの印刷でも一時停止する。

MJPEGのブラウザイベントだけでは、初回フレーム到着や画像が更新し続けているかを確実に判定できない。そのため「配信正常」と断定する状態表示や停止フレームの自動検知はしない。ブラウザが画像エラーを通知した場合はエラーと再接続ボタンを表示する。

## 配信・権限

ブラウザが配信元へ直接接続する。GeoCode-Webサーバーによる映像の中継・保存・配信認証は追加しない。地図の閲覧制限は外部のカメラURL自体を非公開にするものではない。配信元は視聴専用のパスをHTTPS公開し、キャッシュを無効にする。

Pi側の導入は[CameraStreamer](../GeoCode-Web-CameraStreamer/README.md)と[公開手順](../GeoCode-Web-CameraStreamer/docs/PUBLISHING.md)を参照。既存の[Androidカメラ共有](CAMERA_SHARING.md)とは独立した機能。

## 確認

自動テストはURL検証、遅延受信、開閉・折りたたみ・ページ遷移時の解除、印刷、手動再接続を対象とする。実際の通信切断・画角・映像更新はPiと対象ブラウザで別途確認する。

1. 実機のHTTPS `/stream`を記載し、PC・スマートフォンで開く。
2. 開く前の接続が0、開いている間が1、閉じた後が0になることを配信元でも確認する。
3. 折りたたみ、マーカー切替、レイヤ非表示、別タブ、戻る操作で接続が残らないことを確認する。
4. 配信停止後のエラー表示または映像停止を確認し、配信復旧後に再接続する。
5. 印刷・PDFを実行し、カメラの読み込み待ちが発生せず案内文になることを確認する。
