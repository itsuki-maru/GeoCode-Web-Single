# OSRMによる経路検索

ログイン後のPC・モバイルの通常地図とPCの全画面地図で、OSMやローカル地図などの非Google背景から経路を検索できる。Google背景ではGoogle Routes APIを使う。[Google背景地図と経路検索](GOOGLE_MAPS.md)

## 接続設定

OSRMは別途起動し、SQLite版が動くWindowsのプロセスから接続できるようにする。車・徒歩にはそれぞれのプロファイルで前処理済みの経路データを使用する。地図タイル配信用のローカル地図データとは別に準備する。[OSRMの起動手順](https://github.com/Project-OSRM/osrm-backend#quick-start)

1. HTTPやLAN内の接続先を使う場合は、起動プロセスの環境変数 `OSRM_ALLOWED_ORIGINS` にオリジンを登録する。ローカルで車用と徒歩用を別ポートに公開する例では、`http://127.0.0.1:5000,http://127.0.0.1:5001` を指定する。スキームとホストは小文字で記載し、既定ポート（HTTPの80、HTTPSの443）、パス、末尾の `/` は省略する。
2. 管理画面の「OSRM設定」で車用のベースURLを入力する。配信のパス接頭辞は含められる。OSRMの経路APIのパス、認証情報、クエリ、フラグメントは入力欄へ含めない。
3. 「接続確認」で提供範囲内の出発地と目的地を指定し、「設定を保存」で接続先を登録する。徒歩にも対応する場合は、車とは別のベースURLを徒歩用に登録する。
4. 地図を開き直し、非Google背景で経路を検索する。車用の接続先が未登録の場合は、経路検索を表示しない。

公開の接続先はHTTPSを使用する。Tauri起動・サーバー単体モードともに、`OSRM_ALLOWED_ORIGINS` はアプリを起動するプロセスの環境変数から読み取る。設定変更はアプリの再起動で反映する。配布アプリは `.env` を自動で読み込まない。

起動時マイグレーション31・32が、設定版、接続先URL、暗号化APIキーを保存する `osrm_settings` を追加する。移行直後の接続先は未登録。URLとキーを保存した後は次の経路検索から有効になり、移動手段の表示は地図を開き直すと更新される。

### APIキーを使う

認証を使う場合は、OSRMの前段に `X-API-Key` を検証するプロキシを置き、そのプロキシを接続先とする。管理画面で登録したAPIキーは暗号化してSQLiteに保存する。暗号鍵は32バイトをBase64で表した値で、通常は `~/.geocode-web-single/geocode-web-single.env.json` の `osrm_encryption_key` に保存する。

- 設定JSONの項目が未指定または `null` の場合は、起動時の `OSRM_ENCRYPTION_KEY` の値で補完する。両方が未設定で暗号化済みのOSRM APIキーがない場合は、暗号鍵を自動生成して設定JSONへ保存する。
- 実行時は `OSRM_ENCRYPTION_KEY` を優先する。設定JSONに保存済みの暗号鍵はそのまま保持する。
- 明示した暗号鍵の形式が不正な場合は、起動時にエラーになる。設定値を修正して再起動する。暗号化済みのAPIキーがあり、暗号鍵が両方とも失われた場合は、対応する元の暗号鍵を設定JSONか環境変数へ復元する。
- 読み取り専用のローカル地図CLIは暗号鍵の生成・保存を行わない。

APIキーを復元できるように、SQLite DBと設定JSONを一緒にバックアップする。環境変数で暗号鍵を上書きして運用している場合は、使用中の `OSRM_ENCRYPTION_KEY` の値も保管する。

接続先ごとに任意のキーを登録できる。同じURLを使う場合は登録済みのキーを維持できる。URLを変更する場合はキーを再入力するか、削除を選ぶ。管理画面で無効化すると、該当する接続先のキーも削除される。車用を無効化する場合は先に徒歩用を無効化する。

## 利用する

1. 非Google背景を選び、マーカーまたは図形のポップアップで「この場所への経路」を押す。
2. 管理者が設定したOSRMへ現在地と目的地を送信することを確認し、ブラウザーの位置情報利用を許可する。マーカーは登録座標、図形はクリック・タップした地点が目的地になる。ブラウザーの位置情報にはHTTPSまたは `localhost` などのループバック接続が必要。
3. 経路線・概算所要時間・距離とOpenStreetMapの出典を確認する。徒歩用の接続先を登録している場合は、同じ目的地へ徒歩で検索できる。

背景を切り替えるか「経路を消す」を押すと表示を終了する。PCの通常地図と全画面地図では、元の背景を表示できる印刷プレビューに経路と出典を引き継ぎ、印刷・PDF出力できる。[地図印刷・PDF出力](MAP_PRINTING.md)

## API・運用

| API | 用途 |
|---|---|
| `GET /admin/osrm-settings` | 車・徒歩の接続先、キーの設定状態、設定版を取得 |
| `PUT /admin/osrm-settings` | 車・徒歩の接続先とキーを保存・無効化 |
| `POST /admin/osrm-settings/check` | 入力中の接続先とキーで、指定の2地点の経路を確認 |
| `POST /osrm/routes/compute` | アカウント認証と指定された登録済みの非Google背景を検証し、経路を検索 |

経路検索はプロセス全体で60回/分、アカウントあたり10回/分、同時8件まで。出発地または目的地を道路網へ100 m以内で結び付けられない場合や道路経路が存在しない場合は、経路なしと表示する。

経路計算ルーターの応答は `Cache-Control: no-store` とし、アプリは座標や経路を保存しない。OSRMへの要求のURLに座標が含まれるため、OSRMとその前段プロキシでは要求URLをログへ残さないように設定する。

導入時は提供範囲内で車・徒歩、離れた地点で経路なし、接続先停止時のエラーを確認する。PCで同じ背景の印刷・PDFに出典が表示されることも確認する。経路データの更新では別の領域で新しい経路データを用意し、既知の地点で接続確認してから切り替える。
