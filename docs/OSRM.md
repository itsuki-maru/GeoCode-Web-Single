# OSRMによる経路検索

ログイン後のPC・モバイルの通常地図とPCの全画面地図で、OSMやローカル地図などの非Google背景から経路を検索できる。Google背景ではGoogle Routes APIを使う。[Google背景地図と経路検索](GOOGLE_MAPS.md)

## 接続設定

接続先には、Single版が公開するローカル道路網か、別途起動したOSRMを指定できる。外部OSRMでは車・徒歩の各プロファイルで前処理したデータを使う。[OSRMの起動手順](https://github.com/Project-OSRM/osrm-backend#quick-start)

1. HTTPやLAN内のOSRMを使う場合は、呼び出すSingle版の `~/.geocode-web-single/geocode-web-single.env.json` に `"osrm_allowed_origins": "http://127.0.0.1:3000"` のように許可するオリジンを指定し、Single版を再起動する。複数のオリジンはカンマで区切る。スキームとホストは小文字で記載し、既定ポート（HTTPの80、HTTPSの443）、パス、末尾の `/` は省略する。公開のHTTPS接続先は通常、この例外許可を必要としない。
2. 管理画面の「OSRM設定」で車用のベースURLを絶対URLで入力する。配信のパス接頭辞は含められる。OSRMの経路APIのパス、認証情報、クエリ、フラグメントは入力欄へ含めない。
3. 「接続確認」で提供範囲内の出発地と目的地を指定し、「設定を保存」で接続先を登録する。徒歩にも対応する場合は、車とは別のベースURLを徒歩用に登録する。
4. 地図を開き直し、非Google背景で経路を検索する。車用の接続先が未登録の場合は、経路検索を表示しない。

新規セットアップでは `osrm_allowed_origins` は空文字列になる。旧版で環境変数 `OSRM_ALLOWED_ORIGINS` を使っていた場合は、更新後の初回だけ同じ環境で通常起動またはサーバー単体起動（`-s`）する。設定JSONにこの項目がない場合に限り、有効なオリジンがJSONへ移行する。以後はJSONを編集して再起動する。JSONに `""` または `null` を指定すると、環境変数の値にかかわらず接続例外は0件になる。

起動時マイグレーション31・32が、設定版、接続先URL、暗号化APIキーを保存する `osrm_settings` を追加する。移行直後の接続先は未登録。URLとキーを保存した後は次の経路検索から有効になり、移動手段の表示は地図を開き直すと更新される。

### 作成済みのローカル道路網を使う

1. 配信するSingle版の `local-tiles gui` で「経路」→「GeoCode-Webへの経路配信」を開く。「HTTP配信を有効にする」にチェックを入れ、完成済みの道路網を選ぶ。
2. 同じSingle版から検索する場合は「このSingle版からの接続も許可する」にチェックを入れたまま「配信設定を保存」を押す。許可するオリジンの初期値は `http://127.0.0.1:3000`。ホストやポートを変更している場合はその値に合わせる。別のアプリに配信するだけの場合はチェックを外す。保存すると、管理画面で開いた設定JSONの配信設定を更新し、指定したオリジンを既存の許可先に追加する。同一の許可先は一度だけ登録する。次は道路網が「日本」、許可先が未登録だった場合の保存例。

   ```json
   {
     "local_routing_http": {
       "enabled": true,
       "dataset": "日本"
     },
     "osrm_allowed_origins": "http://127.0.0.1:3000"
   }
   ```

3. Single本体を起動する。起動中なら再起動して反映する。サーバー単体の起動例は `geocode_web_single.exe -s 127.0.0.1:3000`。接続元が別マシンの場合は到達可能なアドレスで待ち受け、起動プロセスの `LOCAL_ROUTING_HTTP_API_KEY` に受信用キーを設定する。キー未設定時はTCPの接続元がループバックの場合だけ受理する。リバースプロキシで転送する場合もキーを設定し、HTTPSと座標を記録しないアクセスログを使用する。
4. **呼び出す側**の管理画面の「OSRM設定」で、車用・徒歩用のベースURLを入力する。提供範囲内の2地点でそれぞれ「接続確認」して保存する。配信側に受信用キーを設定した場合は、両方のAPIキー欄にその値を入力する。

   | 移動手段 | 同じPCでのベースURL |
   |---|---|
   | 車 | `http://127.0.0.1:3000/local-routing/car` |
   | 徒歩 | `http://127.0.0.1:3000/local-routing/foot` |

   別のSingle版から呼び出す場合は、そのSingle版の設定JSONに配信元オリジンを指定する。PostgreSQL版から呼び出す場合は、同版のサーバー環境変数 `OSRM_ALLOWED_ORIGINS` に指定する。別ホストやコンテナから利用するときは、許可オリジンとベースURLの両方に、呼び出すバックエンドから到達できるホスト名・ポートを使う。
5. 通常地図を開き直し、非Google背景上のマーカーや図形で「この場所への経路」を選ぶ。管理GUIは閉じてよい。道路網を同名で作り直すと、新しい完成世代を次の検索から使う。配信を停止するときは「HTTP配信を有効にする」のチェックを外して保存し、Single本体を再起動する。登録済みの許可先は保持される。

管理GUIと、同じSingle本体のローカル配信を使う通常地図・管理画面の接続確認では、車・徒歩ともに、出発地と目的地それぞれの半径500 m以内で通行可能な最も近い道路を探す。外部OSRMに問い合わせる場合の検索半径は各地点100 m。

同じ本体の配信には、上表のように待受ポートへ直接つながるHTTPのベースURLを登録する。独自ドメインやHTTPSのリバースプロキシを経由するURLは外部接続先として扱う。

ローカル配信のHTTP窓口は2地点の `route/v1/driving` と `route/v1/foot` を提供する。座標の順序は経度・緯度。`radiuses` は出発地と目的地の順に、各地点の検索半径をメートルで指定する。既定値と上限は各500 mで、`radiuses=100;100` を指定すると両地点とも100 mになる。該当道路がない場合はHTTP 400の `NoSegment`、道路がつながっていない場合はHTTP 400の `NoRoute` になる。配信側では同時に2件まで処理し、超過時は429、公開対象が見つからないときは503、9.5秒の処理期限に達したときは504を返す。

### APIキーを使う

Single版のローカル経路は `X-API-Key` を直接検証する。外部のOSRMで認証を使う場合は、その前段に `X-API-Key` を検証するプロキシを置き、そのプロキシを接続先とする。管理画面で登録したAPIキーは暗号化してSQLiteに保存する。暗号鍵は32バイトをBase64で表した値で、通常は `~/.geocode-web-single/geocode-web-single.env.json` の `osrm_encryption_key` に保存する。

- 設定JSONの項目が未指定または `null` の場合は、起動時の `OSRM_ENCRYPTION_KEY` の値で補完する。両方が未設定で暗号化済みのOSRM APIキーがない場合は、暗号鍵を自動生成して設定JSONへ保存する。
- 実行時は `OSRM_ENCRYPTION_KEY` を優先する。設定JSONに保存済みの暗号鍵はそのまま保持する。
- 明示した暗号鍵の形式が不正な場合は、起動時にエラーになる。設定値を修正して再起動する。暗号化済みのAPIキーがあり、暗号鍵が両方とも失われた場合は、対応する元の暗号鍵を設定JSONか環境変数へ復元する。
- 読み取り専用のローカル地図CLIは暗号鍵の生成・保存を行わない。

APIキーを復元できるように、SQLite DBと設定JSONを一緒にバックアップする。環境変数で暗号鍵を上書きして運用している場合は、使用中の `OSRM_ENCRYPTION_KEY` の値も保管する。

接続先ごとに任意のキーを登録できる。同じURLを使う場合は登録済みのキーを維持できる。URLを変更する場合はキーを再入力するか、削除を選ぶ。管理画面で無効化すると、該当する接続先のキーも削除される。車用を無効化する場合は先に徒歩用を無効化する。

## 利用する

1. 非Google背景を選び、マーカーまたは図形のポップアップで「この場所への経路」を押す。
2. 管理者が設定したOSRMへ現在地と目的地を送信することを確認し、ブラウザーの位置情報利用を許可する。マーカーは登録座標、図形はクリック・タップした地点が目的地になる。ブラウザーの位置情報にはHTTPSまたは `localhost` などのループバック接続が必要。
3. 経路線・概算所要時間・距離とOpenStreetMapの出典を確認する。徒歩用の接続先を登録している場合は、同じ目的地へ徒歩で検索できる。

背景を切り替えるか「経路を消す」を押すと表示を終了する。PCの通常地図と全画面地図では、元の背景を表示できる印刷プレビューに経路と出典を引き継ぎ、印刷・PDF出力できる。[地図印刷・PDF出力](MAP_PRINTING.md)

## API・運用

| API | 用途 |
|---|---|
| `GET /admin/osrm-settings` | 車・徒歩の接続先、キーの設定状態、設定版を取得 |
| `PUT /admin/osrm-settings` | 車・徒歩の接続先とキーを保存・無効化 |
| `POST /admin/osrm-settings/check` | 入力中の接続先とキーで、指定の2地点の経路を確認 |
| `POST /osrm/routes/compute` | アカウント認証と指定された登録済みの非Google背景を検証し、経路を検索 |

経路検索はプロセス全体で60回/分、アカウントあたり10回/分、同時8件まで。出発地または目的地の検索半径内に通行可能な道路が見つからない場合や、両地点を結ぶ経路が存在しない場合は、経路なしと表示する。

経路計算ルーターの応答は `Cache-Control: no-store` とし、アプリは座標や経路を保存しない。OSRMへの要求のURLに座標が含まれるため、OSRMとその前段プロキシでは要求URLをログへ残さないように設定する。

導入時は提供範囲内で車・徒歩、離れた地点で経路なし、接続先停止時のエラーを確認する。PCで同じ背景の印刷・PDFに出典が表示されることも確認する。経路データの更新では別の領域で新しい経路データを用意し、既知の地点で接続確認してから切り替える。
