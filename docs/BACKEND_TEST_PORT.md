# SQLite版へのバックエンドテスト改善の反映

PostgreSQL版で追加したテストを既存のSQLite版テストと照合し、重複する検証を維持しながら43件を追加した。SQLiteのTEXT型UUID・JSON、必須列、トリガー、トランザクションに合わせてテストデータと失敗注入を調整した。開発用の `.env` や通常のSQLiteファイルは使用しない。

## テストで発見し、承認後に修正した本体の不具合

本体変更は次の2ファイルの各1行のみ。その他の本体・関連設定は作業開始時のハッシュと一致している。

- `src/model/onetime_url.rs`: 日時解析の `%.s` を `%.f` に修正。公開ページの期限判定が解析に失敗して常に未期限切れとなり、期限切れのスナップショットを表示する問題を解消した。管理API・公開GET・パスワードPOSTで期限切れを拒否し、削除失敗もエラーとなることを検証する。
- `src/handler/marker_icons.rs`: SQLiteにない `ILIKE` を `LIKE ... COLLATE NOCASE` に修正。所有者で絞り込み、英字の大文字小文字を区別せず、`%`・`_`・バックスラッシュを文字として検索する。検索のHTTP 500を解消した。

修正前の通常テストで上記不具合を再現したログは `target/coverage/first-attempt/tests.log` に保存した。失敗を期待するテストや新たなignoredへ置き換えてはいない。

また、既存の `common::create_test_user` に `init_test_env()` を追加した。従来は `sqlx::test` から渡されたDBでユーザーを作る経路だけ設定初期化が抜け、単独実行で `APP_TITLE must be set` が発生した。環境変数を削除した子プロセスで、インメモリDB・設定・トークンの作成まで確認する回帰テストを追加した。

## 時刻とタイムゾーン

- 履歴順序・期限切れには固定UTC日時を使用する。未来の有効期限はUTCの現在時刻から十分に離し、固定の将来日をいつか過ぎて失敗する条件にしない。
- 本体が現在時刻を使うログイン待機判定は、完全一致ではなく十分な許容幅と拒否前後の状態で確認する。短いsleepで期限や保存競合を発生させない。
- 公開ページと管理APIで、小数秒なし・ミリ秒・マイクロ秒・ナノ秒の期限判定が一致することを確認する。
- `TZ=UTC`、`Asia/Tokyo`、`America/Los_Angeles` で、認証・共有URL・フォーム・タイル・環境初期化の重点テスト23件がそれぞれ成功した。実行記録は `target/coverage/timezones/run.json`。これはTZ環境変数を変更した検証であり、Windows自体のタイムゾーン設定は変更していない。

## 計測と再実行

計測方法は [scripts/coverage/README.md](../scripts/coverage/README.md)、ファイル別の未到達行は [COVERAGE_BACKEND.md](COVERAGE_BACKEND.md) を参照。

```powershell
python -B scripts/coverage/run_backend.py --offline
python -B scripts/coverage/summarize_backend.py
cargo fmt --all -- --check
```

`cargo-llvm-cov` がPATHにない場合は `--llvm-cov` で実行ファイルを指定する。生のJSON・LCOV・HTML・実行ログ・終了コードは `target/coverage/` に保存し、Git管理しない。

比較用baselineは、承認された2件の修正を適用した同じ本体で、追加前の既存236件だけを実行したもの。最終currentは追加分を含む全件実行である。Tauri起動処理を含む `src/` 全体を両方で同じ範囲で計測する。

既存ignored 4件は、手動性能測定2件、PostgreSQL側の転送成果物が必要な検証1件、手動ブラウザ確認1件。そのまま残し、成功件数には含めていない。

主な残る未検証箇所はTauri起動・OS連携と、フォーム・マーカー・SQLite検索やインポートの一部分岐。行カバレッジは実行到達率であり、ブラウザ・実機の表示やOS連携の十分さを保証する指標ではない。
